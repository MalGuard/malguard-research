An Evidence Ladder for Security Scanners

A security verdict should be traceable to observations, independently attributable sources, and explicit inference boundaries.

TECHNICAL NOTE 0322 OCTOBER 2026~399 WORDS

Research question

How should a defensive tool communicate uncertainty without overwhelming its user? A single red or green badge is fast to read, but it can collapse distinct questions: what was observed, what external sources reported, and what the tool inferred.

We propose an evidence ladder as a reporting framework, not as a trained classifier or a validated detection model.

Level one: directly observed facts

The base layer records facts produced by the local inspection process: file size, SHA-256 digest, container format, archive inventory, URL host and redirect count where observed. Each observation needs a source and timestamp. A file's existence or format is not, by itself, a security verdict.

Observations should be reproducible. If a check fails, the report should say it failed rather than silently omit it.

Level two: corroborated context

The next layer adds attributable context such as a signed publisher release, dated external reputation record or consistent independent observations. Multiple sites repeating a single original report do not automatically count as independent confirmation.

Source reliability and freshness affect interpretation. A report about an older version should not be treated as direct evidence about a new file unless identity is established.

Level three: bounded interpretation

Only after stating observations and context should the system express a conclusion. A conclusion can be 'known concerning indicator', 'no concerning indicator observed by these checks', or 'insufficient evidence'. The wording should describe the scope of the checks and avoid a universal promise that software is safe.

Confidence is not a decorative percentage. Without a calibrated evaluation set and defined outcome, numerical confidence can mislead. Descriptive uncertainty is preferable to invented precision.

Worked example

Suppose a fictional mod archive has a known SHA-256 digest, expected folder layout and no match in one external reputation feed. The tool can report those facts. It cannot conclude that the mod is harmless, because the feed is incomplete and runtime behavior was not observed.

If another source reports a concerning indicator for the exact digest, the report should expose the disagreement, dates and provenance rather than hiding one source behind a single color.

Evaluation plan and limitations

A future empirical study should define a labeled dataset, sampling rules, ground-truth criteria and separate metrics for false positives, false negatives and unknown outcomes. It should document data leakage and temporal drift. None of those measurements has been performed in this publication.

The ladder is a proposed communication framework. Its usefulness should be tested with real users and reproducible evaluation before claims of superior detection or comprehension are made.
